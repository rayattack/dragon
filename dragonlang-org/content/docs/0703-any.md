# No Dynamic Escape Hatch

Most typed languages keep a trapdoor: Go has `interface{}`, Java has `Object`,
TypeScript has `any`. Dragon does not. Writing `Any`, `any`, or `object` as a
type is a compile error, because a value whose domain you cannot write down is a
value you cannot reason about, and the compiler cannot check.

The 16-byte `{tag, payload}` box did not go away. Only the untyped spelling did.
A [union](/docs/0702-union-and-narrowing) is boxed exactly the way `Data` was, its
tag is still read at runtime, and it costs exactly what `Data` cost. The
difference is that its arms are written down, so the compiler knows the whole
set.

## Name the domain

Whatever you were reaching for `Data` to hold, say what it is:

```dragon
type Setting = int | str | bool

s: Setting = 42
print(s)        # 42
```

A value outside the domain is refused where you write it, not three call frames
later:

```dragon
# doc: no-check
type Setting = int | str | bool

s2: Setting = 3.14      # error: float is not one of Setting's arms
```

## Reading a value back

Assigning a union to one of its declared arms is a **checked downcast**: the
compiler emits a tag test that raises `TypeError` if the value is holding a
different arm. That is the thing `Data` could never do, because it had no arm
list to check against.

```dragon
type V = int | str

a: V = "hello"
s: str = a              # holds a str: fine
print(s)
b: V = 7
bad: str = b            # raises TypeError: expected str but got ...
```

When you want to branch instead of assert, narrow with `isinstance` or `match`,
and the arm keeps its full type:

```dragon
type V = int | str

def describe(v: V) -> str {
    match v {
        case int() { return f"number {v + 1}" }
        case str() { return f"text {v.upper()}" }
    }
}
```

Because the arms are closed, that `match` is exhaustiveness-checked: add an arm
to `V` and the compiler lists every `match` that no longer covers it.

## JSON-shaped data

The classic reason to want a dynamic tier is data whose shape you learn at
runtime. The standard library declares that domain once, as a recursive union:

```dragon
from json import Data, loads_obj, as_str, as_obj

const body: str = "{\"user\": {\"name\": \"Ada\"}}"
# type Data = str | int | float | bool | none | list[Data] | dict[str, Data]
doc: dict[str, Data] = loads_obj(body)
name: str = as_str(as_obj(doc["user"])["name"], "")
```

`json` also exports typed accessors that narrow by tag and fall back instead of
failing: `as_str(v, dflt)`, `as_int(v, dflt)`, `as_float(v, dflt)`,
`as_bool(v, dflt)`, `as_obj(v)`, `as_list(v)`. Other modules declare their own
domain the same way: `Value` in `database` for a SQL scalar, `Field` in `struct`
for a packed field.

## "Any type the caller picks"

That is not a dynamic value, it is a *parameter*. Use a
[generic](/docs/0705-generics): it monomorphizes, keeps the caller's real type,
and boxes nothing.

```dragon
def first[T](items: list[T]) -> T {
    return items[0]
}
```

## Containers stay invariant

`list[int]` is a flat `int64[]`; `list[int | str]` is an array of boxes. They are
different layouts, so one never converts to the other by annotation. Build the
literal at the type you want, or copy element-wise.
